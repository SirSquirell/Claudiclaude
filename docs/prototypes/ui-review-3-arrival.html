De aankomst

Het moment waarop de data binnen is en het scherm zich vult. Dat is nu één frame: leeg, en dan alles. Hieronder wat het zou kunnen zijn, met de grens er meteen naast — want dezelfde animatie die hier klopt, is bij elke bereikwissel precies de vertraging die ik in ronde 2 heb afgewezen. Daaronder de verfijning van ronde 1: de exacte waarden, in code.

Het moment zelf

na een sync · één keer per aankomst

Start beide kanten. Links is wat er nu gebeurt: de banner verdwijnt, refresh() loopt, en alles staat er in één frame. Rechts komt hetzelfde materiaal aan in een orde die vertelt wat er gebeurde — eerst de vorm van het geheel, dan de details, dan de regels.

Elke kaart komt apart aan

haalt de poort

Dit was in de vorige versie niet te zien: daar landde alles in één klap, dus leek de aankomst één ding. Het zijn losse kaarten. Elke kaart heeft zijn eigen skelet, zijn eigen veeg en zijn eigen inhoud die opkomt — de tijdstempel rechtsboven elke kaart zegt wanneer die kaart landde, gerekend vanaf de eerste. Zet hem op "alles tegelijk" en het verschil is meteen duidelijk.

Nog niets geladen.

Binnen een kaart heeft elk soort inhoud zijn eigen gedrag: grafieken vegen (520 ms voor de grote, 360 ms voor de kleine), tegels en staven komen op (260 ms, 40 ms na elkaar), en tabelrijen vullen zich (28 ms per rij, dak op tien). Geen enkel cijfer verandert onderweg van waarde.

En de kaarten die nog niet in beeld zijn

mechanisme

Zes kaarten passen niet op één scherm — de echte app heeft er dertien. Als ze allemaal bij de aankomst hun veeg doen, gebeurt de helft daarvan buiten beeld en heb je er niets aan. Dus: een kaart komt aan wanneer hij in beeld komt, één keer, en daarna nooit meer. Scroll in het venster hieronder.

Scroll naar beneden.

Eén IntersectionObserver met { threshold: 0.25 } die zichzelf per kaart afmeldt. Dat past ook bij hoe de app nu al werkt: onScreen() in app.js:1419 bouwt alleen de grafieken van het tabblad waar je op staat, dus grafieken buiten beeld bestaan daar al niet. Dit is dezelfde gedachte, één niveau fijner.

De grens — wat dit niet mag worden

  • Eén keer per aankomst, niet per render. De trigger is "er is nieuwe data binnengekomen", dus na een sync en bij de eerste keer openen. Een bereik- of granulariteitswissel hertekent dezelfde reeks en krijgt niets — daar is het pure vertraging, tientallen keren per dag.
  • Nooit een cijfer dat omhoog telt. Een tegel die van € 0 naar € 37.502 kruipt laat een reeks getallen zien die geen van alle waar zijn. In een app die zijn eindtotaal tegen dat van DEGIRO afrekent tot op de cent is dat de verkeerde grap. De tegel komt op met de waarde er al in.
  • Niets mag wachten op de animatie. Klikken tijdens de veeg werkt gewoon; de veeg is een laag over een scherm dat al leeft. Als de animatie ergens de interactie tegenhoudt, is hij verkeerd gebouwd.
  • Geen skelet dat flikkert. Bij een herhaalde sync staat er al data: die blijft staan op verlaagde opacity, en het skelet komt alleen bij de eerste keer, als er werkelijk niets is. Anders springt de lay-out twee keer per sync.
  • Onder reduced-motion wordt de veeg een crossfade. Een masker dat over het scherm loopt is beweging over een groot vlak, en dat is precies waar die voorkeur voor bestaat. De aankomst blijft, de beweging gaat eruit.

skill: apple-design

Ronde 1 zei wát er moest gebeuren. Dit is hoe — met de curve-tokens uit ronde 2 als basis, zodat het vier keer dezelfde stem is en niet vier keer een eigen keuze.

De tokens waar de rest op rust

styles.css · :root

Vier regels bij de bestaande tokens. Twee curves, twee duren; alles hieronder verwijst hiernaar, dus een latere smaakwijziging is één plek. 

/* Beweging. Twee curves, omdat er twee soorten zijn: iets dat
   aankomt of vertrekt (ease-out), en iets dat over het scherm
   beweegt (ease-in-out). De ingebouwde varianten zijn te slap —
   `ease-out` vertrekt te traag op precies het moment dat de
   lezer kijkt. */
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
--t-press: 100ms;   /* de druk: te voelen, niet te zien       */
--t-surface: 140ms; /* menu, popover: open. Dicht is 110ms.   */

1 · De overlays, per oppervlak

4 plekken

De oorsprong is niet één waarde: elk paneel groeit uit zijn eigen knop. De dialogen zijn de uitzondering — die hangen aan niets en blijven gecentreerd, dus die schalen vanuit het midden.

Oppervlaktransform-originOpen / dicht

Granulariteit .gran .menutop left140 / 110 ms
Kolomkiezer .cols-poptop right — hij staat rechts uitgelijnd onder zijn knop140 / 110 ms
Dialogen .modal, .share-sheetcenter — geen trigger om vandaan te komen160 / 120 ms

En de implementatie kan zonder JavaScript-klassen, omdat de extensie alleen op Chromium loopt: @starting-style voor de intree en transition-behavior: allow-discrete zodat display en ::backdrop meedoen. Dat is de hele dialoog — geen timer, geen .closing-klasse die kan blijven hangen als er iets tussenkomt. 

.modal, .modal::backdrop {
  transition: opacity 160ms var(--ease-out),
              transform 160ms var(--ease-out),
              overlay 160ms allow-discrete,
              display 160ms allow-discrete;
}
.modal { opacity: 1; transform: scale(1); }
.modal::backdrop { opacity: 1; }

/* dicht — en dus ook het startpunt van open */
.modal:not([open]), .modal:not([open])::backdrop { opacity: 0; }
.modal:not([open]) { transform: scale(0.97); }

@starting-style {
  .modal[open] { opacity: 0; transform: scale(0.97); }
  .modal[open]::backdrop { opacity: 0; }
}

4 · reduced-motion, gericht in plaats van totaal

styles.css:2299

De sterrenselector eruit, en in plaats daarvan noemen wat er weg moet: verplaatsing. Kleur, oppervlak en opacity blijven — dat is wat vertelt dat een knop je gehoord heeft. 

@media (prefers-reduced-motion: reduce) {
  /* Beweging weg. Niet de reactie. */
  button:active,
  .rail-nav button:active,
  .menu button:active { transform: none; }

  /* De oppervlakken die de druk aangeven blijven staan. */
  .rail-nav button:active,
  button.primary:active { background: var(--surface-3); }

  /* Overlays komen op zonder te groeien. */
  .menu, .cols-pop, .modal { transition: opacity 120ms ease; }
  .menu.closed, .cols-pop.closed { transform: none; }

  /* De aankomst wordt een crossfade — zie boven. */
  .chart-box.arriving { transition: opacity 200ms ease; mask-image: none; }

  /* En de grap staat al uit. */
  .frown [class*='frown-'] { animation: none; }
}

Dit is langer dan de regel die het vervangt, en dat is het punt: * { transition-duration: 0.01ms } is kort omdat het niet nadenkt. Vier benoemde uitzonderingen zijn te lezen, en te testen.
